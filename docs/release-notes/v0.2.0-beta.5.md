# Automation Sandbox __TAG__

Preview NuGet package artifact release. Rolls up the work merged since `v0.2.0-beta.4`.

## Highlights

- **Deleted-element false heals driven to zero on both benchmark fixtures (#370, #375).** Three
  per-component gates the weighted similarity score cannot override:
  - **Per-component name gate.** When the stale locator had a name, the winning candidate's
    `NameScore` must clear `SimilarityWeights.MinimumNameScoreWhenNamed` on its own. `Balanced`
    and `Conservative` set `0.30`; `SimilarityWeights.Default` ships disabled. HandBrake
    `Balanced` false-heal `9.3 % → 7.6 %`, precision `90.7 % → 92.4 %`, recall unchanged.
  - **Repository ownership reconciliation.** `SelfHealingEngine.ReconcileAgainstRepository`
    (opt-in, default off) re-resolves every *other* authored locator against the same captured
    tree before accepting a confident match, and declines the heal as `ownership-conflict` when
    the winning candidate is already another locator's confident identity. Heuristic-only, no
    extra LLM traffic.
  - **Per-component descendant gate.** `SimilarityWeights.MinimumChildSignatureSimilarity`
    (`0.50` on `Balanced` / `Conservative`, disabled on `Default`). `UiElementSnapshot.Capture`
    now records the multiset of an element's direct child `ControlType`s (`UiElementInfo`
    schema addition, optional, no-op on pre-existing snapshots and on leaf locators); a
    container locator's candidate must still hold matching child types.
  - **Combined:** deleted-element false heals across the committed ablation datasets go from
    `40 %` (HandBrake) / `28 %` (ShareX) at the shipped default to **zero on both**, with zero
    genuine-rename verdict flips. See `benchmark-calibration.md` §14/§15 and
    `integration-existing-suite.md` §5.
- **Desktop intent pipeline flow report (#372).** `IntentDesktopAutomationPipeline` now emits
  the same `IntentFlowReportDocument` (JSON + HTML) as the web pipeline — schema v4, adds
  `Platform` (`"web"` | `"desktop"`) and `FlaUiCSharpTestCode`. Every per-step field the web
  report renders (matched locator, `BestCandidateScore` / `SemanticScore` / `RunnerUpScore`,
  review status, `AssertionKind` / `ExpectedValue`) is populated for desktop.
- **Reasoning-model response recovery (#378).** OpenAI-compatible endpoints that return their
  chain-of-thought in a non-standard `message.reasoning` field and truncate the JSON answer in
  `message.content` (observed with Groq's `openai/gpt-oss-120b`) are now handled:
  `OpenAiHealingProvider` folds `message.reasoning` in, and the response parser recovers
  `candidateId` / `confidence` from an object cut off inside its `reasoning` value.
- **Consumer-facing docs and packaging.** A "Which Package Do I Need?" selection table and a
  "What `0.2.0-beta` commits to" API-stability tier table in the README (#337, #371); per-package
  NuGet READMEs, tags and a refreshed icon (#338, #340); a single-sourced [documentation
  hub](https://mustafasercansak.github.io/automation-sandbox/docs/) with the Pages homepage
  links fixed (#361, #362, #366).
- **New guides and studies.** [Adding self-healing to an existing suite](https://mustafasercansak.github.io/automation-sandbox/docs/integration-existing-suite.html)
  (#343), [How it compares](https://mustafasercansak.github.io/automation-sandbox/docs/comparison.html)
  with Healenium / Testim / Mabl / Ranorex (#344, both now fully bilingual), the
  [HandBrake case study](https://mustafasercansak.github.io/automation-sandbox/docs/blog/case-study-handbrake.html)
  (#357), the [LLM false-heal study](https://mustafasercansak.github.io/automation-sandbox/docs/blog/llm-false-heal-study.html)
  (#341), and research notes on Linux AT-SPI (#17) and macOS AXUIElement (#373) desktop
  discovery backends.
- **1.0 readiness.** `versioning-and-stability.md` §3 gains a condition-based release trigger
  and a live status tracker (#368); the "≤ 10 % HandBrake Balanced false-heal" beta-exit
  criterion is now a regression guard.
- **Release flow.** The version bump is decoupled from the nuget.org publish (#336): the
  release workflow verifies the just-published package as a clean-room consumer would, then
  opens the SSoT-bump follow-up PR itself.

## Fixes

- **Reasoning-model parsing (#378):** a response whose answer object is cut off mid-string no
  longer fails the parse — `LlmHealingPrompt.ParseResponse` closes the open string and braces
  and salvages the completed fields; a genuinely answerless response still throws.
- **Pages homepage links (#361):** every documentation link on the GitHub Pages homepage
  resolved to a 404 because bare paths did not carry the `docs/` prefix; `DocumentationSiteIntegrityTests`
  now scans every reader-facing Markdown surface, not just `docs/*.md` (#363).
- **Bilingual parity (#369):** criterion #6 is precisely scoped to the numbered `docs/*.md`
  guides; `comparison.md` and `integration-existing-suite.md` are now fully bilingual and
  enforced by the parity test.
- **Release SSoT-bump step (#367):** the follow-up-PR step uses a plain `--force` push (a fresh
  branch has no remote-tracking ref for `--force-with-lease`), no longer swallows a real
  `gh pr create` failure, and reports the PR URL to the job summary.

## Known Limitations

- **Calibration:** higher confidence thresholds reduce false heals, but the magnitude does not transfer between applications. Calibrate against your own UI history; the shipped `MinimumConfidence` is `0.50`.
- **Accuracy:** the three per-component guards (#370, #375) drive deleted-element false heals to **zero on both committed fixtures** at no auto-heal recall cost. This is not an absence detector — it is three targeted gates (label contradiction, another locator owns the candidate, the container's contents changed). A deleted element that heals onto a leaf control no other test uses and whose label happens to match would still slip through; none occurs on HandBrake or ShareX, but a third application could resurface one. Perceptual-hash and LLM-pairwise absence signals remain unmeasurable on the current fixtures (`benchmark-calibration.md` §15).
- **LLM providers:** covered by mocked-HTTP unit tests; the nightly workflow gates one known ground-truth agreement scenario against independent providers. Release creation does not run a live gate. Reasoning models that put their answer in `message.reasoning` are handled but a clean-JSON model (`GROQ_MODEL = llama-3.3-70b-versatile`) is still preferable (#378).
- **Platform:** desktop automation is Windows-only (FlaUI / UIA3). The heuristic engine and the web path are cross-platform and verified on Linux in CI. Linux desktop discovery via AT-SPI (#17) and macOS via AXUIElement (#373) are research notes, not shipped backends.

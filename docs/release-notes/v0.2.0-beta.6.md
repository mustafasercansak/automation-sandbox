# Automation Sandbox __TAG__

Preview NuGet package artifact release. Rolls up the work merged since `v0.2.0-beta.5`.

## Breaking Changes

- **Library namespaces migrated to `AutomationSandbox.*` (#399).** Every package's root namespace
  changed from its bare form (e.g. `SelfHealing`, `LlmHealing`, `UiModel`) to `AutomationSandbox.*`
  (e.g. `AutomationSandbox.SelfHealing`). Update `using` statements; nothing else about the public
  API's shape changed. This is the first release where the published packages actually match this
  namespace - it landed on `main` after `v0.2.0-beta.5` was already on nuget.org, which left the
  documented quickstart broken against the live package until now (#415).
- **Public API surface frozen and several DTOs made immutable (#400).** `ScoreComponents`,
  `PlaywrightLocatorSuggestion`, `IntentElementCandidate`, and `IntentDesktopElementCandidate` now
  take named constructor arguments and expose get-only properties - replace
  `new ScoreComponents { NameScore = 0.8 }` with `new ScoreComponents(nameScore: 0.8)`.
  `IntentElementCandidate` copies its supplied locator suggestions into a read-only list at
  construction. `AssertionCodeEmitter`, `CodeGenerationUtilities`, `IntentCandidateReviewEvaluator`,
  `IntentRecordingLookupTable`, and `IntentTextScoring` are now internal - depend on the public
  planners, exploration bridges, and test generators instead. See `public-api-audit.md` for the
  full Tier 1/2/3 rationale.

## Highlights

- **LLM-consensus heals now enforce the same false-heal gates as heuristic heals (#416).** The
  per-component name and descendant/child-signature gates (#370, #375) were only ever computed for
  the heuristic winner; an LLM-consensus pick was gated on evidence coverage and provider agreement
  alone. A name- or content-mismatched candidate agreed on by two providers could be accepted as
  confident. Both gates are now computed and enforced identically regardless of `HealResult.Source`.
- **Bounded traversal across the pipeline (#419, #425, #426).** The web DOM capture path gains
  `MaxDepth`/`MaxElements`/`Timeout` bounds matching the desktop path's `DiscoveryOptions`; three
  previously-unbounded recursive tree walks (`SelfHealingResolver.Flatten`,
  `UiElementTreeExtensions.Flatten`, `WebElementMapper.Map`) are now iterative with a depth cap.
  A pathologically deep or wide tree (large SPA, framework-generated markup) truncates gracefully
  instead of risking a stack overflow or an unbounded capture payload.
- **LLM pipeline hardening (#417, #420, #427).** One malformed entry in the optional
  `LLM_CUSTOM_PROVIDERS` config no longer discards every already-configured built-in provider.
  `LlmIntentPlanningPrompt` gets the same XML boundary-tag prompt-injection hardening
  `LlmHealingPrompt` already had. A multi-step plan response truncated mid-JSON by a reasoning
  model now recovers its completed steps instead of falling back to the deterministic planner
  entirely.
- **Calibration accuracy fix (#418).** `TreeCalibrator`'s probe fixtures never populated
  `ChildControlTypeSignature`, so the descendant/child-signature gate was silently inert during
  every `Calibrate()` run - the reported Balanced/Conservative precision numbers didn't reflect it.
- **Healing report writes are O(1), not O(n) (#424).** `HealingReportFileSink` switched to an
  append-only JSON Lines format; recording a heal no longer deserializes and rewrites the entire
  prior history on every call.
- **CI and repo hygiene.** Every workflow job has an explicit `timeout-minutes` (#428); the
  `githooks/commit-msg` AI-attribution guard is wired into onboarding and, for the first time,
  actually executable (#423, #432 - it was tracked as non-executable and silently never ran).
- **Positioning.** The roadmap now explicitly names desktop healing as the commercial focus and
  defines the evidence bar for closing #401 - real external FlaUI integrations and organic
  version-drift data, not synthetic fixtures - as an explicit 1.0-blocking gate (#402).

## Fixes

- **Consensus quorum (#388):** the nightly consensus gate requires an actual 2-of-N agreement
  across the full configured provider pool, not a hardcoded Groq+Mistral pair.
- **False-consensus flagging (#392):** evaluation scenarios with no clear ground truth are flagged
  as undecidable rather than silently counted toward agreement.
- **Discovery multi-targeting (#396):** `net48;net8.0-windows` restored - FlaUI 5 is not
  net48-only.
- **`UiTreeWalker` resilience (#425):** a non-whitelisted exception from one element no longer
  aborts an entire discovery walk when `ContinueOnElementError` is enabled; it's recorded as a
  per-node warning instead.
- **Dependency alignment (#411):** all three `System.Text.Json` references (UiModel, LlmHealing,
  SelfHealing) pinned to `10.0.12`, closing an `NU1605` downgrade error.
- **Documentation:** the getting-started guide's Step 3 now shows the project-setup commands it
  previously assumed (#422); the documentation hub links three previously-orphaned pages -
  `external-validation.md`, `public-api-audit.md`, `dora-metrics.md` (#421); the Ollama
  getting-started example no longer implies single-provider consensus is sufficient (#398).

## Known Limitations

- **Calibration:** higher confidence thresholds reduce false heals, but the magnitude does not
  transfer between applications. Calibrate against your own UI history; the shipped
  `MinimumConfidence` is `0.50`.
- **Accuracy:** the per-component gates (#370, #375, and now #416 for LLM picks) drive
  deleted-element false heals to zero on both committed fixtures at no measured auto-heal recall
  cost, but this is not a general absence detector - see `benchmark-calibration.md` §15 for the one
  documented residual scenario and why it isn't closed.
- **External validation:** all benchmark evidence remains synthetic mutations over two real
  application trees (HandBrake, ShareX). No external user integration or organic (non-synthetic)
  drift dataset exists yet; #401 explicitly blocks 1.0 on this and the evidence bar it requires is
  documented in `external-validation.md`.
- **LLM providers:** covered by mocked-HTTP unit tests; the nightly workflow gates one known
  ground-truth agreement scenario against independent providers. Release creation does not run a
  live gate.
- **Platform:** desktop automation is Windows-only (FlaUI / UIA3). The heuristic engine and the web
  path are cross-platform and verified on Linux in CI. Linux desktop discovery via AT-SPI (#17) and
  macOS via AXUIElement (#373) remain research notes, not shipped backends.

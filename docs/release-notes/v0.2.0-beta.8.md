# Automation Sandbox __TAG__

Preview NuGet package release. Rolls up the work merged since `v0.2.0-beta.7`, and brings the
published `AutomationSandbox.Cli` tool level with its documentation: the tool published as
`0.2.0-beta.7` was built before `--selector`, `--compact`, the deeper tree limit and the exit-code
fix below, so a volunteer who installed it and followed the guide hit "Unrecognized argument".

## Breaking Changes

No public type or member was removed or had its signature changed: the public API inventory has 74
added types and none removed. Three behaviour changes can be noticed by a caller:

- **`automation-sandbox-heal` answers exit code `2`, not `1`, for a mistake on the command line
  (#646).** An unknown or misspelled flag, a flag with no value, a missing `--tree`, both or neither
  of `--expected`/`--selector`, an unknown `--profile` and no arguments at all used to exit `1`,
  which means "not confident". A CI gate that sends `1` to review therefore read a typo such as
  `--profil balanced` as an ordinary result and nobody learned the tool had not run. The usage text
  now goes to stderr in that case, so stdout stays empty; only `--help` prints it to stdout (exit
  `0`). A script that treated `1` as "my command line was wrong" must now check for `2`.
- **A `BoundingRectangle` with a NaN or infinite number now means "no geometry" (#639).** The
  constructor turns all four values into zero, so the rectangle equals `BoundingRectangle.Empty`, is
  not usable, and the scorer leaves the position signal out, exactly as it already did for an empty
  rectangle (WPF's `Rect.Empty` is positive and negative infinity). Before, such a rectangle was
  scored as if the number were real and the result could not be written as JSON. **This can change a
  score without any error**: in one test file the same candidate moved from low confidence (0.59) to
  confident (0.83) because the position evidence is now left out and the other signals are
  renormalised. The evidence gate (coverage of at least 0.40) still applies.
- **`UiTreeSerializer` accepts trees up to 256 elements deep (#638).** The default JSON limit of 64
  had allowed only 31 nested elements, and a deeper tree failed with "possible object cycle", which
  named the wrong cause. `UiTreeSerializer.MaxElementDepth` and `MaxJsonDepth` are new public
  constants; a tree past the limit is a `JsonException` that names the depth. The CLI and the browser
  capture payload use the same bound. This only widens what is accepted.

## Highlights

- **`automation-sandbox-heal` (package `AutomationSandbox.Cli`).** `--selector` heals from a
  Playwright locator when no snapshot was ever recorded (#616; the output is wrapped as
  `{ PartialEvidence, DerivedExpected, Result }` and the same gate applies); `--compact` prints a
  result that is not many times larger than the input (#620); stderr is written as UTF-8 so
  non-ASCII element names survive a Windows console (#621); it always writes its result for a
  scored tree (#639). Exit codes: `0` confident, `1` not confident, `2` it could not run.
- **Row context for identical siblings (#617).** `UiElementInfo.RowContext` holds the text of the
  other elements in the row or list item an element sits in (`UiRowContext.Annotate`, called by
  `WebElementMapper`; the browser capture computes the same), and `SimilarityWeights.RowContextWeight`
  (0.10) compares it by word overlap. It counts, in the score and in `EvidenceCoverage`, only when
  the stale locator recorded one, so snapshots without it score exactly as before. A list whose rows
  each hold an identical `Connect` button is no longer ambiguous when only the row differs.
- **Keyless spelling check for `ContentAnalysis` (#538, #548).** `SpellingChecker` reads Hunspell
  dictionaries you supply (none are bundled) through the new dependency `WeCantSpell.Hunspell`, so
  spelling findings need no API key and no text leaves the machine. Accuracy fixes found by
  auditing real pages: Turkish suffixes written with affix flag 0, `stem'suffix` forms, a cut-off
  last word, and `style`/`script`/SVG text. The duplicate-word check no longer reports a repeat
  across table cells, list items or a heading and the paragraph after it, repeated numbers or code
  names (#550). `WebDiscoveryOptions.MaxTextLength` (#541, default 160, unchanged) lets a caller
  keep more element text for a content check.
- **`SiteCrawler` can honour `robots.txt` and read `sitemap.xml` (#557).** `SiteCrawlOptions.RespectRobotsTxt`
  (default off, so existing crawls are unchanged) skips disallowed URLs, honours `Crawl-delay`, and
  refuses a disallowed start page; `SeedFromSitemap` queues sitemap pages one level below the start
  page. `RobotsTxt` and `SitemapParser` are public, network-free parsers.
- **Issue-automation building blocks in `AutomationSandbox.LlmHealing` (about 70 added public types,
  #562 to #590 and #601).** A healing-free `ITextModel` contract with adapters for OpenAI-compatible
  endpoints, Claude, Gemini and Ollama; label-based routing of a task to a drafting model and a
  reviewer; an issue gate; triage, CI-failure and documentation tasks with an independent review
  that can only block; a deterministic CI-log classifier. All of it is additive and opt-in, reads
  keys from environment variables only, and is not used by the healing resolver, whose rules are
  unchanged. `LessonIndexBuilder` and `LessonRetriever` (#561, #629) can quote past issues, pull
  requests and commit messages into a prompt; **retrieval has not been shown to help review**
  (repeated replays over ten real defects with three models found no benefit, and one model scored
  lower with lessons in every run), so it is off unless a lessons file is given.
- **Smaller fixes.** `IntentFlowReportFileSink` writes through a temporary file like the other report
  sinks and no longer overwrites the document's own `GeneratedAt` (#640). Dependencies:
  `System.Text.Json` 10.0.14 and `Microsoft.Playwright` 1.64.1.

## Not in the packages

These are in the repository and verified by CI but are not published to NuGet in this release:
`automation-sandbox-agent` (read-only issue triage), `automation-sandbox-audit` (site typo audit),
`automation-sandbox-mcp` (a read-only Model Context Protocol server, **not tried against a real MCP
client**), the `site-audit` composite action, and the samples and capture examples.

**Security fix in the repository, for anyone who uses the `heal` composite action from `main` or a
pinned ref (#636).** The action wrote its inputs straight into a bash script, so a value that held a
quote or `$(...)` ran as shell on the caller's runner. A caller that passed a value derived from a
pull request (a branch name, a path) could have had a command injected. Every input now reaches the
script through the environment and is validated first; a bad value stops the step with exit code `2`.
Update any pinned reference to a commit that has this change. The packaging workflows were moved to
the same rule (#637).

## Known Limitations

- **Calibration:** higher confidence thresholds reduce false heals, but the magnitude does not
  transfer between applications. Calibrate against your own UI history; the shipped
  `MinimumConfidence` is `0.50`.
- **Accuracy:** the per-component gates drive deleted-element false heals to zero on both committed
  fixtures, but this is not a general absence detector, and independent model agreement is not a
  correctness guarantee (every unanimous verdict on a deleted element across four measured runs was
  a false heal).
- **External validation:** all benchmark evidence is synthetic mutations over two real application
  trees (HandBrake, ShareX). No independent integration or organic drift dataset exists yet; #401
  blocks 1.0 on it.
- **Interactive discovery:** `SiteCrawler` follows `<a href>` links only and never clicks.
- **Spelling check:** it judges single words only, so it cannot find grammar errors, and brand
  names, jargon and code that are not on the allow list are reported as misspellings. The bundled
  English dictionary of the upstream project is small; use `--lang` with `en-GB` and an allow list.
- **LLM providers:** covered by mocked-HTTP tests; a nightly workflow gates one ground-truth
  agreement scenario. Release creation does not run a live gate.
- **Platform:** desktop automation is Windows-only (FlaUI / UIA3). The heuristic engine and the web
  path are cross-platform and verified on Linux in CI.

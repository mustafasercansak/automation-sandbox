# Automation Sandbox __TAG__

Preview NuGet package release. The only change since `v0.2.0-beta.8` is the move of the whole
repository from .NET 8 to .NET 10 (#652), because .NET 8 reaches end of support in November 2026.
There is no change to scoring, the resolver, the CLI options or the public API.

## Breaking Changes

- **The packages no longer contain a `net8.0` asset.** The nine libraries now ship `netstandard2.0`
  and `net10.0` (`Discovery` ships `net48` and `net10.0-windows`). A project that targets .NET 8
  still restores the packages: NuGet picks the `netstandard2.0` asset, and no public type or member
  changed. What a .NET 8 project loses is only a build compiled for its own runtime.
- **`AutomationSandbox.Cli` (`automation-sandbox-heal`) needs the .NET 10 runtime.** It was `net8.0`
  before. On a machine with only .NET 8, `dotnet tool install` or the first run fails; install the
  .NET 10 runtime or SDK. This is the change most likely to be noticed, and it is a loud failure,
  not a silent one.
- **Building the repository needs SDK 10.** `net10.0` used to be added only when SDK 10 was present;
  it is now a fixed target, so an SDK 8 alone cannot build the solution.

## What this release changes

- Every library, tool, sample and test project targets `net10.0` (the libraries keep
  `netstandard2.0`, the Windows projects keep `net48`). CI installs SDK 10 only.
- The test suite now runs on `net10.0` (Linux) and `net48` (Windows). Before, the `net10.0`
  assemblies were compiled and packed but never run by a test; now the shipped assemblies are the
  tested ones.
- Docs, package READMEs and sample READMEs name .NET 10 where they named .NET 8.

## Known limitations

- **External validation:** no independent integration and no organic version-drift dataset exists
  yet; #401 blocks 1.0 on it. Repository-owned samples and synthetic mutations do not count.
- **Platform:** desktop automation is Windows-only (FlaUI / UIA3). The heuristic engine and the web
  path are cross-platform and verified on Linux in CI.
- **LLM providers:** covered by mocked-HTTP tests; a gated workflow checks one ground-truth
  agreement scenario. Release creation does not run a live gate.
